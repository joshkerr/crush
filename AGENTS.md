# Crush AI Agent Development Guide

This document provides comprehensive guidance for AI agents working in the Crush codebase. Crush is a terminal-based AI coding assistant built in Go that integrates with multiple LLM providers, Language Server Protocols (LSPs), and Model Context Protocol (MCP) servers.

## Project Overview

**Type**: Go CLI application with Bubbletea TUI (Terminal User Interface)
**Go Version**: 1.25.5
**Architecture**: Service-oriented with SQLite database, pub/sub event system, and agent orchestration
**Primary Dependencies**:
- `charm.land/bubbletea/v2` - Terminal UI framework
- `charm.land/fantasy` - LLM abstraction layer
- `charm.land/lipgloss/v2` - Terminal styling
- `github.com/charmbracelet/catwalk` - Provider/model database
- `github.com/ncruces/go-sqlite3` - Database
- `github.com/openai/openai-go/v2` - OpenAI API client
- `github.com/modelcontextprotocol/go-sdk` - MCP integration

### Key Architecture Patterns

#### 1. Service Pattern
Services define interfaces in the package and embed `pubsub.Subscriber[T]` for event-driven architecture:

```go
type Service interface {
    pubsub.Subscriber[Message]
    Create(ctx context.Context, sessionID string, params CreateMessageParams) (Message, error)
    Get(ctx context.Context, id string) (Message, error)
    List(ctx context.Context, sessionID string) ([]Message, error)
    Update(ctx context.Context, message Message) error
    Delete(ctx context.Context, id string) error
}

type service struct {
    *pubsub.Broker[Message]
    q db.Querier  // Database access
}

func NewService(q db.Querier) Service {
    return &service{
        Broker: pubsub.NewBroker[Message](),
        q:      q,
    }
}
```

#### 2. Pub/Sub Event System
All major services use pub/sub for loose coupling:
- `internal/pubsub/broker.go` provides the event broker
- Events: `pubsub.CreatedEvent`, `pubsub.UpdatedEvent`, `pubsub.DeletedEvent`
- Subscribers use `Subscribe(ctx)` and receive `Event[T]` on channels

```go
// Publishing
s.Publish(pubsub.CreatedEvent, session)

// Subscribing
ch := s.Subscribe(ctx)
for event := range ch {
    switch event.Type {
    case pubsub.CreatedEvent:
        // Handle creation
    }
}
```

#### 3. Context Usage
- **Always** pass `context.Context` as the first parameter to functions
- Use `t.Context()` in tests for automatic cancellation
- Context keys defined as typed constants:
  ```go
  type sessionIDContextKey string
  const SessionIDContextKey sessionIDContextKey = "session_id"
  ```

#### 4. Concurrency
- `internal/csync/maps.go` provides thread-safe `Map[K, V]`
- Use `sync.RWMutex` for read-heavy workloads
- Services often have internal mutexes for state protection

#### 5. Database Layer
- SQLite database via `sqlc` code generation
- Migrations in `internal/db/migrations/*.sql`
- Queries in `internal/db/sql/*.sql`
- Generated code in `internal/db/*.go`
- All services accept `db.Querier` interface for testability

## Code Style & Conventions

### Imports
Group imports in three sections (goimports/gofumpt style):
1. Standard library
2. External packages
3. Internal packages (`github.com/charmbracelet/crush/internal/...`)

Example:
```go
import (
    "context"
    "fmt"
    "log/slog"

    "charm.land/fantasy"
    "github.com/charmbracelet/catwalk/pkg/catwalk"

    "github.com/charmbracelet/crush/internal/config"
    "github.com/charmbracelet/crush/internal/session"
)
```

### Naming Conventions
- **Exported**: PascalCase (`SessionAgent`, `CreateMessage`)
- **Unexported**: camelCase (`sessionAgent`, `createMessage`)
- **Types**: Use type aliases for clarity: `type AgentName string`
- **Constants**: Use typed constants with `iota` for enums, group in `const` blocks
- **Interfaces**: Define in consuming packages, keep small and focused
- **Variables**: No one-letter names except standard Go conventions (i, j, k in loops)

### Error Handling
```go
// Return errors explicitly
if err != nil {
    return fmt.Errorf("failed to get session: %w", err)
}

// Sentinel errors as package-level vars
var ErrRequestCancelled = errors.New("request was cancelled")

// Use errors.Is/As for checking
if errors.Is(err, ErrRequestCancelled) {
    // Handle
}
```

### Structs & Types
```go
// Use struct embedding for composition
type service struct {
    *pubsub.Broker[Message]

// Group related fields
type Model struct {

// JSON tags use snake_case
```

### Key Testing Practices

#### 1. Use testify for assertions
```go
import (
    "github.com/stretchr/testify/assert"
    "github.com/stretchr/testify/require"
)

// require.* stops test on failure
require.NoError(t, err)
require.NotNil(t, result)

// assert.* continues test on failure
assert.Equal(t, expected, actual)
assert.True(t, condition)
```

#### 2. Parallel tests
```go
func TestSuite(t *testing.T) {
    for _, tc := range testCases {
        t.Run(tc.name, func(t *testing.T) {
            t.Parallel()  // Run tests in parallel
            // Test code
        })
    }
}
```

#### 3. Table-driven tests
```go
testCases := []struct {
    name     string
    input    string
    expected string
}{
    {name: "simple case", input: "foo", expected: "bar"},
    {name: "edge case", input: "", expected: "default"},
}

for _, tc := range testCases {
    t.Run(tc.name, func(t *testing.T) {
        actual := process(tc.input)
        assert.Equal(t, tc.expected, actual)
    })
}
```

#### 4. Test environment setup
```go
func TestYourFunction(t *testing.T) {
    // Use t.TempDir() for temporary directories (auto-cleanup)
    tmpDir := t.TempDir()
    
    // Use t.SetEnv() for environment variables
    t.SetEnv("CRUSH_DEBUG", "true")
    
    // Use t.Context() for automatic cancellation
    ctx := t.Context()
    
    // Test code
}
```

#### 5. Mock providers for testing
```go
func TestWithMockProvider(t *testing.T) {
    // Enable mock providers to avoid real API calls
    originalUseMock := config.UseMockProviders
    config.UseMockProviders = true
    defer func() {
        config.UseMockProviders = originalUseMock
        config.ResetProviders()
    }()
    
    config.ResetProviders()
    
    providers := config.Providers()
    // Test with mock data

```

#### 6. VCR for recording API interactions
```go

func TestAPICall(t *testing.T) {
```

## Important Gotchas & Non-Obvious Patterns

### 1. Golden File Updates
When test output changes intentionally, you must update golden files:
```bash
go test ./internal/tui/components/core -update
```
Without `-update`, tests fail when output doesn't match snapshots.

### 2. Mock Providers in Tests
Always enable mock providers to avoid real API calls and costs:
```go
config.UseMockProviders = true
defer func() {
    config.UseMockProviders = originalUseMock
    config.ResetProviders()
}()
```

### 3. Context Cancellation
Services subscribe to context cancellation. Always pass through `t.Context()` in tests:
```go
// Good
result, err := service.Process(t.Context(), data)

// Bad - context never cancels
result, err := service.Process(context.Background(), data)
```

### 4. Pub/Sub Cleanup
Always unsubscribe or cancel context to avoid goroutine leaks:
```go
ctx, cancel := context.WithCancel(context.Background())
defer cancel()

ch := service.Subscribe(ctx)
// Use ch
```

### 5. Thread-Safe Maps
Use `csync.Map[K, V]` instead of `map[K]V` with manual locking:
```go
// Good
m := csync.NewMap[string, int]()
m.Set("key", 42)
val, ok := m.Get("key")

// Avoid
var mu sync.RWMutex
m := make(map[string]int)
mu.Lock()
m["key"] = 42
mu.Unlock()
```

### 6. Agent Tool Sessions
Agent tools can create sub-sessions for nested operations:
```go
// Parse agent tool session ID
messageID, toolCallID, ok := sessions.ParseAgentToolSessionID(sessionID)
if ok {
    // This is a sub-session from a tool call
}
```

### 7. Windows Path Handling
- Use forward slashes in code: `path/to/file`
- `filepath` package handles conversion automatically
- Watch out for shell scripts - may need PowerShell alternatives

### 8. Bubbletea TUI Updates
TUI updates are message-driven:
```go
func (m model) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg := msg.(type) {
    case tea.KeyMsg:
        // Handle key press
    case SomeCustomMsg:
        // Handle custom message
    }
    return m, nil
}
```

### 9. LSP Integration
- LSP servers configured per-language in `crush.json`
- Servers must be installed separately (e.g., `gopls` for Go)
- Used for context gathering, not direct code manipulation

### 10. Database Transactions
The `db.Querier` interface abstracts queries, allowing transactions:
```go
// db.DB implements Querier for direct queries
// db.Tx implements Querier for transactional queries
```
